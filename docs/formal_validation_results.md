# 正式 Validation 实验记录

## 1. 实验范围与设置

本项目使用本地 Qwen3-8B 4-bit 量化基座，通过 MLX-LM LoRA 学习单轮工具选择、参数生成，以及澄清和不支持操作的判断。

输出采用自定义 JSON 协议。本轮评估调用决定与说明文字，不连接业务数据库、不执行真实工具。

| 分区 | call | clarify | unsupported | 合计 |
| --- | ---: | ---: | ---: | ---: |
| Train | 360 | 180 | 60 | 600 |
| Validation | 120 | 60 | 20 | 200 |

训练只使用 Train 更新参数；训练后单独运行 Validation 推理。本轮未使用 Test。

正式训练运行：`run_20261017T014551_717380Z`。

- 训练：1 个 epoch，共 600 次更新，每 150 步保存 checkpoint。
- LoRA：最后 16 层，rank=8，scale=20，dropout=0。
- 学习率：1e-5；batch size=1；梯度累积=1；seed=42。
- 最大序列长度：2048；启用梯度检查点；屏蔽 prompt 损失。
- 五组 Validation 使用相同生成设置：关闭 thinking，temperature=0，max_tokens=256。

## 2. 自动评估口径与结果

“全部自动检查通过”要求：

1. 原始输出能够严格解析为 JSON 对象。
2. 输出满足动作结构和工具接口约束。
3. action 与参考答案一致。
4. 参考答案为 call 时，工具名称和全部参数完整匹配。

clarify 和 unsupported 的说明文字语义质量另外审查。

## 3. Checkpoint 选择

训练配置预先记录的比较顺序为：

1. 全部自动检查通过率。
2. 参考 call 的完整调用匹配率。
3. 训练步数更少者。

step450 与 step600 的前两项指标相同，自动通过和失败的样本集合也一致，因此按第三项选择 step450，随后与 baseline 开展说明文字审查。

候选权重：

`adapters/formal/run_20261017T014551_717380Z/0000450_adapters.safetensors`

step450 依据正式 Validation 结果选定，并在 Test 前锁定。
最终 Test 评估已完成，结果见 [正式 Test 评估记录](formal_test_results.md)。

## 4. Baseline 与 step450 说明审查

本轮为导师指导的非盲审，覆盖两种模型的全部 80 条参考非调用请求。

动作或接口检查失败的输出标为 not_applicable，不进入说明文字通过率的分母，但仍计入整体失败。原始模型输出保留，改写建议单独记录。

| 状态 | baseline | step450 |
| --- | ---: | ---: |
| pass | 52 | 61 |
| needs_improvement | 4 | 0 |
| not_applicable | 24 | 19 |
| pending | 0 | 0 |

具备审查资格的说明中，通过率分别为：

- baseline：52/56（92.86%）。
- step450：61/61（100%）。

baseline 的四条说明问题包括：三条引入未经验证的商品信息管理接口，一条混淆筛选阈值与实际库存数量，并引入工具定义未提供的库存非负业务规则。

结合自动检查：

- baseline：120 条正确调用 + 52 条合格说明，共 172/200（86%）。
- step450：120 条正确调用 + 61 条合格说明，共 181/200（90.5%）。

仅比较自动检查，step450 改善 6 条、退化 1 条，净增加 5 条，通过率增加 2.5 个百分点。

合并说明审查后，step450 改善 10 条、退化 1 条，净增加 9 条，合并通过率增加 4.5 个百分点。

本轮说明审查仅覆盖 baseline 和 step450。五组 checkpoint 的横向比较继续使用自动指标。

## 7. 结论边界

结果来自人工模板与参数组合生成的 Validation 数据。模板家族与参数隔离不等于已经验证真实业务请求上的广泛泛化能力。

本轮只有一个训练 seed；说明审查为导师指导的非盲审，尚未开展统计显著性验证和专门耗时评估。

90.5% 表示这 200 条 Validation 请求上的调用决定与说明文字合并通过率，不代表 Test 表现。

最终 Test 已在固定方案下单独完成，结果与错误分析见 [正式 Test 评估记录](formal_test_results.md)。
真实工具执行和多轮 Agent 不属于本项目已完成范围。
